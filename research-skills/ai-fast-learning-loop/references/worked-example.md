# 案例：以"自动驾驶技术"跑完阶段一

用来校准输出的**深度和颗粒度**。注意每一份视角分析的结论都不重叠，简报最后把问题重新定义了一遍。

## 第 1 步 · 五视角 STORM

五个角色分别落到了这些真实身份上：

| 角色 | 具体身份 | 核心结论 |
|---|---|---|
| 实践者 | 自动驾驶工程师 / 运营者 | 技术已经在路上运行，但安全尚未被充分证明 |
| 学者 | 机器人学研究者 | 从感知-决策-控制链条给出系统性框架 |
| 怀疑者 | 安全研究者 / 批判型技术评论者 | 关注的是失败情境——哪些长尾场景会出事 |
| 经济学家 | 成本与商业可行性分析者 | 技术或可更安全，但要看成本是否算得过账 |
| 历史学家 | 技术史 / 交通史研究者 | 以上判断都成立，但最终决定时间表的是制度与文化，而非代码 |

五句话交叉总结里最要紧的是最后一句：**技术不是决定变量，制度与文化才是。**

## 第 2 步 · 矛盾突破

- **共识**：技术已具备基本可行性；安全验证尚未完成
- **盲区**：五方都没提"能跑之后"的事——能跑多广、多安全、多便宜、多合法

盲区指向的地方就是认知边界：不是"能不能做出来"，而是"做出来之后谁来兜底、怎么定价、怎么合规"。

## 第 3 步 · 综合简报

1. 五个关键发现（按重要性降序）
2. **隐藏关联**：长尾场景的覆盖成本 与 单车盈利模型 互相牵制——越想覆盖长尾，单车成本越高，商业化越难成立
3. **行动建议**：把评估重心从"技术可行性"转到"单车经济模型 + 责任归属制度"
4. **前沿问题**：当事故不可避免时，责任如何在制造商、软件方、驾驶员之间分配

简报的核心判断：**"自动驾驶能否实现"已不是核心问题，真正的问题发生在"能跑之后"。技术并非瓶颈，长尾场景、单车盈利才是决定变量。**

## 第 4 步 · 同行评审自检

斯坦福教授视角会追问的点：

- "安全尚未被充分证明"——证据是事故率数据还是里程数据？两者口径不同
- "成本算不过账"——是按哪一年的传感器价格算的？摩尔定律是否已经改变了结论
- "制度与文化决定时间表"——这是可验证的判断，还是不可证伪的托词

注意：第 4 步的作用不是推翻简报，而是**给每条结论标上可信度**，让读者知道哪几条能直接拿去决策、哪几条还得再查。

---

## 这个案例示范了什么

1. **视角必须真的分开**——五份分析读起来像五个不同的人写的，不是一段话换五个开头
2. **价值在争议处**——共识清单是背景音，盲区清单才是真信息
3. **简报要重新定义问题**——从"能不能做"改成"能跑之后怎么办"，这才是决策级产出
4. **自检不是走过场**——至少找出三条口径不清或不可证伪的表述
