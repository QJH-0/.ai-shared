# Project Chain Atlas（项目链路图谱）

把代码库讲清楚，难点从来不是「有哪些模块」，而是**「一次真实的用户动作，在系统里走了哪条路」**。
读者拿到模块清单仍然不知道系统怎么跑；拿到链路才会。

本技能产出两样东西，缺一不可：

1. **分页可点击的 HTML 手册**——一页一条链路，可分享锚点、可键盘翻页、总图节点可点。
2. **交互式链路模拟器**——把链路的**时序与状态迁移**演出来（节点按真实顺序点亮、事件流按 seq 落、
   HITL 真的挂起等你点、取消在下一个检查点才收口）。静态图永远做不到这一层。

---

## 什么时候用 / 不用

**用**：接手陌生仓库要写上手文档；项目链路复杂、跨多个模块和进程；要给别人讲清楚系统；
要交付「能跑给你看」的演示而不只是文字。

**不用**：只要 API 参考手册（那是文档生成）；只要按模块组织的 wiki（用 `repo-wiki`）；
只问某个具体函数怎么实现（直接读代码回答即可）。

---

## 非协商项（这四条决定了产出有没有价值）

1. **证据来自源码，不来自既有文档。** 逐文件读 `src/`，所有结论标注 `file:line`。
   既有文档可能已经过时——转述文档等于把过时信息二次固化。文档只用来交叉验证，不作为唯一来源。
2. **按数据流 / 控制流切链路，不按目录结构切。** 一条链路 = 一次用户可见的完整动作，
   它会横跨多个模块、进程、存储。按目录切出来的东西读者无法建立整体图景。
3. **每条链路必须四要素齐全**：起点 / 关键节点 / 分支 / 终点，外加**触发条件**与**关联链路**。
   缺了「谁触发它、它又触发谁」，读者只能看到一堆孤立片段。
4. **降级路径也算链路。** 组件故障时系统怎么退化（降级到什么、留什么痕）是系统设计的重要部分，
   漏掉它，读者会在生产环境第一次踩坑时才发现。

---

## 技术选型：不自己造轮子

**唯一自研的是「语义驱动的模拟器引擎」**——因为现成库不含那层语义（见 `html-atlas-spec.md` 3.0）。
图表、动效、壳、检索、高亮、主题这些一律先找成熟实现，按三层递进：

1. **平台原生优先（0 字节）**：CSS `transition` / `@keyframes`、Web Animations API、
   View Transitions API、`@media (prefers-color-scheme: dark)` 暗色、`<dialog>`、
   IntersectionObserver……多数交互与动效都能覆盖，不需要任何库。
2. **需要库就内联进单文件**：用 `scripts/embed_asset.py` 把库（Prism 高亮、MiniSearch 离线检索、
   svg-pan-zoom 图缩放等）打进 HTML，保住离线。
3. **页面多了就换成熟文档框架**（MkDocs Material / VitePress / Starlight），放弃单文件。

判断标准只有一条：**手写的那段逻辑，是不是本技能的独有价值？不是，就换成成熟实现。**
完整的「需求 → 成熟方案 → 体积/许可 → 判据」对照表见 `references/ui-tech-choices.md`。

## 工作流

### 第 1 步：建立证据底座（不要跳）

先做三件事，再动笔：

- **摸清入口**：`main.py` / `app.ts` / `cmd/` / `router` —— 找出 HTTP 端点、定时任务、事件消费者。
  这些是链路天然的起点。
- **摸清状态载体**：数据库表、缓存键、队列、对象存储、检查点。链路本质是状态在它们之间的迁移。
- **摸清横切关注点**：认证、限流、事件/日志、错误映射、配置。它们不属于任何单条链路，
  但几乎每条链路都会穿过——单独成链路。

用 `Explore` 子代理并行摸这几块比顺序读快得多；但**关键路径的代码要自己读**，
因为链路文档的价值全在细节（谁先谁后、先落库还是先发通知、失败怎么收口）。

### 第 2 步：穷举链路清单

先写**总索引表**，再逐条展开。表的列固定为：
`编号 | 链路 | 起点 | 终点 | 触发条件 | 关联链路`。

穷举的检查方法（这三问能逼出遗漏）：

- 用户能做的**每一个动作**，从点击到落库走完了吗？（发起 / 取消 / 续跑 / 上传 / 导出 / 回滚 / 改配置）
- 系统**被动响应**的每一条路走了吗？（断线重连、进程重启恢复、组件故障降级、后台任务）
- 每条链路的**失败分支**走了吗？（校验失败、并发冲突、超时、权限不足）

主链路与其子分支要分开成页（例如「主链」与「直答分支 / 人工介入分支 / 并行分支」），
否则单页会太长，读者抓不住层次。

### 第 3 步：逐条写链路

每条链路按 `references/chain-template.md` 的固定骨架写。骨架统一的价值是：
读者读第二页时就知道该往哪看，不用重新适应结构。

写图解时**用成熟 DSL 描述、再离线预渲染成静态 SVG 内联**：不要手算坐标，也不要在页面里引图表
运行时（CDN 或内联 mermaid.js 都会破坏离线，还多背数 MB）。DSL 选型与渲染/回填命令见
`references/html-atlas-spec.md` 第二节，工具是 `scripts/render_diagrams.py`。Mermaid 覆盖链路
（flowchart）/ 时序（sequence）/ 状态机（state）三类图，D2、Graphviz、PlantUML 可选。
图内节点用 DSL 的链接语法指向对应链路页（如 `click A href "#p-l1"`），读者才能顺着走。

写代码实例时，**摘最能说明问题的那几行**并标 `file:line`，不要整段贴。
读者要的是「跳到源码去看」的锚点，不是把源码复制一份（那也会立刻过时）。

### 第 4 步：做交互式模拟器

这是本技能区别于普通文档的核心。要点：

- **语义驱动，不是贴图。** 节点名取自真实代码里的常量，事件名取自真实的事件枚举，
  seq 递增对应真实的序号分配逻辑，状态迁移对应真实的状态机。做不到这一点就是装饰品。
- **必须能演示「时序」**：人工介入（interrupt）要真的阻塞等待、协作式取消要在下一个检查点才生效、
  进程中断要能演示「恢复后已执行节点不重跑」。这些是静态图完全表达不了的东西。
- **提供场景切换**：直答 / 完整流程 / 人工介入开与关 / 中途取消 / 进程中断续研 / 异步任务链。

直接用 `assets/atlas-scaffold.html` 作为起点——它已经把分页壳、导航、模拟器引擎、
以及**三个已知坑的修复**都写好了（见下节）。改场景脚本即可，不要从零写。
（分层说明：**图表**用成熟 DSL 换掉手绘；**模拟器引擎**刻意自研，因为它的价值是按真实语义
驱动状态迁移，现成动画库不含这层语义。见 `references/html-atlas-spec.md` 3.0。）

### 第 5 步：验证（不可省）

跑 `scripts/browser_regression.py`，用**真实无头浏览器**做交互回归。

**为什么不能用自建 DOM 桩代替**：桩在 `closest()`、`innerHTML=''` 是否清空子节点、
事件冒泡这些行为上与真实浏览器有差异，而这些差异**恰好会掩盖最常见的那类 bug**。
实测中，两个真实缺陷（场景切换无效、侧边目录点击不跳转）都只在真实浏览器里现形。

验证至少要覆盖：导航（侧边目录 / 页内链接 / 翻页按钮 / 图内可点节点 / 键盘 / URL 锚点）、
模拟器场景切换（含**运行中切换**）、模拟器关键交互（人工介入挂起与恢复、取消）。
详见 `references/verification.md`。

## 三个必须避开的坑（都踩过，都会让交付物看起来「能用」其实不能用）

1. **异步循环 + 共享可变状态必须有代际令牌。** 「重置」如果只替换状态对象而不作废在飞的循环，
   旧循环会继续往新状态上灌数据——表现为「切换后还是上一个场景的内容」。
   脚手架里的 `runToken` 就是干这个的：`reset()` 自增，循环每次 `await` 后比对，不一致即静默退出。
   同理，被 `await` 挂起的 Promise 也要能被 `reset()` 解除，否则旧循环永久泄漏。

2. **事件委托的选择器要覆盖全部跳转入口。** 当页面上同时存在 `data-goto` 与 `data-page`
   两类跳转标记时，只匹配其中一个会让**另一类入口静默失效**（表现为「有的地方能点、有的不能」）。
   用一个委托同时匹配两者。

3. **不要用「先写 innerHTML 再 querySelector 回填」的写法。** 一次性转义拼接更短、更稳，
   也去掉了对 DOM 查询结果的二次依赖。

## 产出与交付

- 交付物：`docs/链路手册.html`（或按项目惯例命名），单文件、离线可开。
- 图表**源文件一并保留**（如 `diagrams/*.mmd`）：后续链路变了只需改源、重跑渲染脚本刷新图，
  不必重画。这也是用 DSL 而非手绘 SVG 的收益之一。
- 若项目已有同名单页版，按项目惯例移入 `.trash/`，并在结果里列出移动清单。
- 交付时说明：链路清单、每条的验证状态、**未验证项**、以及是否需要用 `repo-wiki` 补一份模块化文档。

  ```bash
  python <skill_dir>/scripts/browser_regression.py <skill_dir>/assets/atlas-scaffold.html <skill_dir>/scripts/scaffold_probe.js
  ```
