# 机制解释：把零件讲成系统

## 判据与边界

| 用户要的是 | 走哪条 |
|---|---|
| 搞懂某个机制 / 链路 / 设计点 | 本 skill（八项全量） |
| 一句话能答清的关系型问题（如"这个字段谁写"） | 本 skill 的**轻量模式**：定位 + 证据 + 显式说明省略了哪些项 |
| 改代码 | 直接改；解释服务于改动，只守下面两条硬底线 |
| 更直观 / 可视化 / 一图看懂 / 讲解视频 | **先**用本 skill 定内容与结构，**再**由 `skills/ai-output-readability` 定载体 |

分工：本 skill 管**答什么、按什么顺序答**；载体（文本 / 图 / 网页 / 视频）由 `ai-output-readability` 决定，此处不重复定义。

## 两条硬底线

1. **骨架先行**：第一段必须给全局骨架——分层（如事实层 / 通知层 / 视图层或等价划分）与关键位置概念（写入位置 vs 读取位置）。骨架先于任何细节；只答问句字面而不给上下游，视为不合格。
2. **证据优先**：结论落 `file:line`、SQL 或可执行命令；不接受"一般来说""应该"。

## 输出顺序

1. 骨架（分层 + 关键位置）
2. 八项契约（下表）
3. 自检题 + 易误解点（第 8 项，放文末）

## 八项输出契约

不适用项**显式标"不适用 + 原因"**，不得省略不提。

| # | 项 | 要求 |
|---|---|---|
| 1 | 定位 | 一句话：它在哪一层、上游是谁、下游是谁 |
| 2 | 术语 | 每个关键词给定义，并说明"它不是什么"（日志≠队列、尾部≠读位点、缓冲≠存储） |
| 3 | 时序 | 从产生到消费的编号步骤，关键步给 `file:line` |
| 4 | 数据形态 | 内存对象 / 线格式 / 存储行，各给一个具体样例 |
| 5 | 失效矩阵 | 依赖不可用、消费者慢、连接断开、进程重启，逐项说明谁兜底、最坏多久 |
| 6 | 取舍 | 为什么不选另一种常见做法、代价是什么、什么条件下该切换 |
| 7 | 证据 | `file:line`、SQL 或可执行命令 |
| 8 | 自检 | 3 个读完应能回答的问题 + 3 条最容易被误解的点 |

### 失效矩阵样例

| 故障 | 谁兜底 | 最坏影响时长 | 恢复路径 |
|---|---|---|---|
| 依赖不可用 | `retryQueue`，退避上限 30s（配置项 `retry.maxBackoffMs`） | 30s，之后进死信队列 | `src/queue/retry.ts:88` |
| 进程重启 | WAL 重放 | ≤ 一个 `wal.fsyncIntervalMs`（当前 1s）的未落盘区间 | `src/wal/replay.ts:42` |

> 时长必须能指到配置项或代码路径；没有依据就写"未实测 / 取决于 X 配置"，不给凭空数字。

## 禁止

- 只解释被问到的那一个零件，不挂到骨架上。
- 使用未定义术语，尤其一词多义（尾部 / 位点 / 游标、存储 / 缓冲、队列 / 日志）。
- 绝对化结论不给边界；给出无依据的量化估算。
- 重复上轮结论而不补缺口。

## 多轮纪律

- **纠错义务**：发现先前回答不准确，首句显式写"上一轮说法不准确"并给正确表述，不静默改写。
- **重复追问信号**：同一概念被第二次追问，一律视为上次解释不完整；本轮补齐骨架与边界，而不是换角度重述。第三次仍不完整，停止展开细节，先交付一页纸骨架供对齐。
- **跨轮连贯**：后续答案挂回同一骨架（"这是第几层、哪个位置"），不另起一套隐喻或命名。

## 反模式

| 反模式 | 问题 |
|---|---|
| 直接答问句字面，不交代上下游 | 读者拿到零件，装不回系统，下一轮必然再问 |
| 八项里挑顺手的答，省略项不标注 | 读者无法判断是"不适用"还是"没查" |
| 失效矩阵只写"会重试"不给时长依据 | 无法评估 SLO，等于没答第 5 项 |
| 先讲载体（画了张图）再补结构 | 图会跟着错误结构一起返工 |
