# 反模式检测库

## 适用与判定

- 按 `lifecycle-gates.md` 的任务范围、组件与服务等级选择相关条目；无相关影响的小任务不因缺容量、监控或计划文档自动命中。
- 检测方法须可执行；检索结果是候选线索，不能把 grep 命中直接当作缺陷或输出实际凭据值。
- 颜色只提示风险，不定义 P0/P1。单实例不自动构成工具脚本的阻断问题，凭据泄露按真实安全影响处理。
- 缺陷须有触发路径、适用要求、影响与证据；严重程度、状态、豁免和不可豁免项唯一源为 lifecycle-gates「门禁状态与报告」。

## 🔴 1. 能跑就行（Runnable-Is-Enough）

| 项 | 内容 |
|---|---|
| **现象** | 验收标准只有「功能可用」；无 SLO、无容量、无观测、无回滚；用「先上线再优化」推进 |
| **检测** | ① 计划文档中检索不到 `SERVICE_TIER` 与 SLO 取值；② 交付记录中「验证结果」只有功能测试，无压测/观测/回滚证据；③ 出现「后续优化」「暂时这样」等表述 |
| **危害** | 上线即成为技术债与故障源；故障时无观测无回滚，只能靠人肉救火 |
| **修复** | 按 `nfr-baseline.md` 定级取值；按 `lifecycle-gates.md` 补齐该级证据；无证据不得标记完成 |

## 🔴 2. 单点故障（Single Point of Failure）

| 项 | 内容 |
|---|---|
| **现象** | 应用/数据库/缓存/MQ/网关/证书/定时任务调度存在单实例；「双机热备」但同宿主机同可用区 |
| **检测** | ① 逐组件清单核对实例数与故障域；② 问「这台机器挂了会怎样」，答不出或答「全挂」即命中；③ 定时任务无分布式锁 |
| **危害** | 任一组件故障即整体不可用；RTO 无法满足 |
| **修复** | 按 `resilience-and-ops.md` §一 消除单点、跨故障域冗余、实测切换、保留容量冗余 |

## 🔴 3. 无监控（No Observability）

| 项 | 内容 |
|---|---|
| **现象** | 只有零散 `print`/`console.log`；无 trace_id；告警只有 CPU/内存裸指标；告警发出去无人处置 |
| **检测** | ① 日志样本是否含 `trace_id`/`span_id`/`error.type`（见 `nfr-baseline.md` §6.1）；② 是否暴露延迟分位与错误率指标；③ 每条告警是否对应 Runbook 与责任人；④ 问「这个接口 P99 多少」，答不出即命中 |
| **危害** | 故障只能等用户投诉才发现；根因定位时间从分钟级拉长到小时级 |
| **修复** | 补齐日志字段、指标、链路追踪；告警改由 SLI/SLO 推导并配 Runbook（`resilience-and-ops.md` §七） |

## 🔴 4. 无压测（No Load Testing）

| 项 | 内容 |
|---|---|
| **现象** | 「本地跑了一下没问题」；容量数字靠估；从未做全链路压测；数据量为空的压测结论被当作依据 |
| **检测** | ① 是否存在压测报告文件（含脚本路径、并发模型、实测分位）；② 压测数据量是否与生产同一数量级；③ 容量结论是否含推导链（日活→频次→峰值系数） |
| **危害** | 容量上限未知，首个高峰即雪崩；扩容无依据，成本与风险双输 |
| **修复** | 按 `nfr-baseline.md` §4.3 的倍数要求压测；产出含瓶颈定位的报告；容量模型附推导过程 |

## 🔴 5. 无回滚（No Rollback）

| 项 | 内容 |
|---|---|
| **现象** | 发布靠「出问题手动改回去」；无可执行回滚步骤；回滚判据靠人工感觉；schema 变更不可逆且无回退路径 |
| **检测** | ① 发布说明中是否有回滚命令、预计耗时、数据一致性处理；② 回滚判据是否量化（指标 + 阈值 + 持续时间）；③ 回滚是否实际演练过 |
| **危害** | 一次失败发布即长时间故障；不可逆变更可能造成数据损坏 |
| **修复** | 按 `resilience-and-ops.md` §六 提供预案 + 量化判据 + 演练；schema 走扩展-迁移-收缩三步（`system-design.md` §5.1） |

## 🔴 6. 硬编码（Hardcoding）

| 项 | 内容 |
|---|---|
| **现象** | 地址、端口、超时、阈值、密钥、环境判断写死在代码里；业务代码散落读环境变量；多环境靠改代码区分 |
| **检测** | ① 全仓 grep 具体凭据值（token/password/secret/AK）确认无残留；② grep 域名、IP、`http://`、端口常量；③ 同一配置项在多个文件重复出现；④ `if (env == "prod")` 式分支 |
| **危害** | 环境不可迁移、密钥泄露、配置漂移、变更需重新发版 |
| **修复** | 集中配置层 + 默认值 + 缺失行为说明；凭据走环境变量或密钥管理服务（`nfr-baseline.md` §七）；IaC 管理拓扑 |

## 🟡 7. 同步阻塞（Synchronous Blocking）

| 项 | 内容 |
|---|---|
| **现象** | 在请求主链路里做耗时操作（发邮件/短信、生成报表、调用慢第三方、大批量写库）；无超时的同步调用；用睡眠轮询等待结果；单个慢下游拖垮整个线程池 |
| **检测** | ① 主链路是否存在耗时 > 500 ms 的同步外部调用；② 是否存在无超时的调用；③ 是否存在 `sleep`/轮询等待；④ 线程池/连接池是否被单一慢依赖占满（饱和度指标） |
| **危害** | 延迟分位被慢依赖绑架；线程池耗尽导致全接口不可用 |
| **修复** | 异步化（MQ / 后台任务）+ 超时 + 隔离舱（独立线程池）；耗时任务移出主链路并返回任务 ID（`system-design.md` §四） |

## 🔴 8. 共享数据库（Shared Database）

| 项 | 内容 |
|---|---|
| **现象** | 多个服务/模块直接读写同一批表；跨模块 JOIN；绕过对方服务改其数据；「共享库省事」 |
| **检测** | ① 同一张表是否存在多个写入方（检索写入点）；② 是否存在跨服务 JOIN 或跨模块直接访问对方表；③ 表是否有明确唯一归属方 |
| **危害** | 表结构变更牵一发动全身；写入冲突与数据不一致无法定位；无法独立部署与扩展 |
| **修复** | 明确每张表的唯一写入方（`nfr-baseline.md` §八 数据归属）；跨模块改走接口或事件；确需共享时降级为只读副本或视图并登记决策 |

## 🔴 9. 无版本 API（Unversioned API）

| 项 | 内容 |
|---|---|
| **现象** | 接口无版本标识；字段说删就删、语义说改就改；无契约文件；旧版本无公告期直接下线 |
| **检测** | ① 对外接口是否有机器可读契约且与实现同源；② 是否有版本载体（URL / Header / 字段级演进声明）；③ 最近一次不兼容变更是否升版本并公告；④ 是否有旧版本调用量统计 |
| **危害** | 调用方随发布随机崩溃；无法灰度与并行运行新旧版本；发布不可回滚 |
| **修复** | 按 `system-design.md` §二 定义契约与版本载体；不兼容变更升版本 + 公告期 + 调用量埋点；废弃返回弃用提示 |

## 🔴 10. 非功能需求后置（NFR-Deferred）

| 项 | 内容 |
|---|---|
| **现象** | 「先把功能做完，性能/安全/监控/容灾后面再说」；需求文档只有功能需求；DoR/DoD 不含非功能项 |
| **检测** | ① 计划文档是否含非功能需求章节（定级、SLO、容量、观测、安全、数据生命周期）；② 是否出现「后续优化」「二期再做」且无责任人/失效期；③ 安全项是否被排到上线后 |
| **危害** | 非功能属性无法事后追加——架构决定上限，事后补只能推倒重来 |
| **修复** | 按 `nfr-baseline.md` 在需求阶段定级取值；按 `lifecycle-gates.md` 的 DoR 卡住入口；安全项不得后置 |

## 补充高危模式

| 模式 | 检测 | 修复 |
|---|---|---|
| 吞异常返回默认值且不记日志 | grep 空 `catch`/`except` 块，检查返回值语义 | 降级可以，但必须留日志（含异常类型与消息） |
| 异常转 `return False`，调用方不检查返回值 | 检索返回状态而非抛异常的函数，核对所有调用点是否判返回值 | 调用方必须判返回值；否则改为抛异常 |
| 降级分支条件不可达 | 逐条检查降级条件的可达性（异常路径上该变量是否真会被置为 None） | 让条件可达，或删除伪降级 |
| 伪健康检查 | readiness 只返回常量 `true`；liveness 里查下游依赖 | readiness 反映依赖就绪，liveness 只判进程自身 |
| 无上限队列 | 检索队列/线程池构造参数，队列容量为 `Integer.MAX_VALUE`/无界 | 设上限 + 定义满队列行为 |
| 无超时调用 | 检索 HTTP/RPC/DB 客户端构造，超时字段缺省 | 全部显式设超时，保证下游之和 < 上游 |

## 使用方式

方案评审核对相关风险；代码审查按检测方法取证并记录真实缺陷；上线评审核对修复与有效证据。复盘重复问题时提出补充检测或规则修订建议，经授权后修改相应维护源。
