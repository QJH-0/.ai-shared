# Standards — 生产级标准库

本目录把「能跑就行」升级为「可上线、可扩展、可观测、可容灾、可演进」的**强制基线**，覆盖完整生命周期：调研 → 需求分析 → 开发 → 测试 → 系统设计与运维。

## 唯一维护源声明

- **可度量数值**（SLO / RTO / RPO / 延迟分位 / 容量 / 覆盖率阈值 / 重试参数）**只在本目录维护**。`AGENTS.md`、`agents/*.md`、`skills/*` 一律只引用，不复述数值——副本间的任何数值差异视为缺陷（见 `AGENTS.md`「核心哲学 → 单一维护源」）。
- **枚举**：`SERVICE_TIER` 的唯一维护源是 `nfr-baseline.md`；`GATE_STATUS` 与 `RELEASE_GATE` 的唯一维护源是 `AGENTS.md`「门禁状态定义」。其他文档只引用取值，不重复定义。
- 分发：本目录位于 `agents/` 之下，经目录联接（Junction）自动同步到 8 个工具目录，**无需单独建链接**（见 `HARDLINK_INVENTORY.md` 第三节）。

## 约束等级词表

全目录统一使用三个词表达强制程度，禁止使用「尽量 / 适当 / 快速 / 稳定 / 较好」等不可度量的表述：

| 词 | 含义 | 违反后果 |
|---|---|---|
| **必须** | 强制项。不满足即不得进入下一阶段 / 不得放行 | 阻断：`GATE_STATUS=FAILED` 或 `RELEASE_GATE=NOT_READY` |
| **应该** | 推荐项。不满足须在计划或交付记录中书面说明理由与替代措施 | 警告：降级为 `PASSED_WITH_WARNINGS` |
| **可以** | 可选增强，无强制后果 | 无 |

## 豁免规则

任何强制项都**不允许**以「后续优化」「暂时这样」「能跑就行」为由跳过。确需豁免时，必须同时具备四个要素，缺一即视为未豁免：

1. **书面理由** —— 写清为何本阶段无法满足；
2. **责任人** —— 具名到人（不是「团队」）；
3. **失效期** —— 明确的日期或触发条件（如「下一个迭代结束前」）；
4. **补偿措施** —— 豁免期内如何控制风险。

豁免记录写入项目 `.agent_docs/plans/` 下的计划文档或 `.agent_test/gate/report.md`，并据此把 `RELEASE_GATE` 判为 `READY_BY_EXCEPTION`。

## 与项目既有规范的关系

- 项目自带更严格的规范时，**取更严格者**；项目规范更宽松时，以本目录为下限。
- 项目有历史遗留代码不满足基线时，不得「一刀切重写」：按 `AGENTS.md`「改动分级」处理，在计划文档中登记存量差距清单与收敛路径（含责任人与时间点），新增代码必须立即达标。
- 本目录与 `AGENTS.md` 冲突时，以 `AGENTS.md` 为准并立即修正本目录。
