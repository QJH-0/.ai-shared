## AGENTS.md 治理文档修订

对 `AGENTS.md`（硬链接分发到各工具目录的唯一维护源）做了 7 项修订，同步改 `agents/tester.md` 与 `.gitignore`。

**关键决策与结论**

- **委派约束**：原「禁止委派 Agent 独立完成测试执行与结论判定」与同文件「多 Agent 协作」章节（tester 执行测试）自相矛盾。改为只约束**深度**——门禁结论必须由实际执行者本人基于原始输出作出、禁止向下级 Agent 二次委派，并要求跨层交付附原始证据（命令 / 退出码 / 日志路径）。`tester.md` 去掉重复的禁止表述，只保留角色特有的「只读检索可委派」例外。
- **纯净原则第 4 条**：由项目专属的「服务器端源码与调用端 md5 完全一致」泛化为通用「单一维护源」（原名称「都算一致」已改）。仓库内无其他引用，改名安全。
- **跨模块变更判定**：产品模块清单（Agent / 检索 / 索引 / 图片 / Skill / MCP）替换为通用判定类别。
- **文件删除处理**：删除「交付前 `.trash/` 必须为空」这一没有合法执行者的终态；明确 AI 只移动不删除、`.trash/` 必须列入 `.gitignore`、交付时提示用户手动清理。
- **元规则**：原文声称「本文件仅保留门禁规则与指引指针，不二次抄写细节内容」与事实不符且已产生措辞漂移，改为可执行的内容归属路由规则（跨仓库底线留本文件 / 项目专属外移项目文档 / 角色流程归 agents / 技能细节归 skills）。
- **分支名不含斜杠**：标注为本机环境特有约束，避免被当作通用 git 规范。

`AI_READ_FIRST.md` 说明只有 `AGENTS.md`（硬链接）、`skills\`、`agents\`（目录联接）会分发到各工具目录，**新建顶层目录或文件不会同步**。因此长规则不宜拆到新目录；要外移只能放进 `skills/` 或 `agents/`。

## 第二轮：约束删除 + agents 审计 + 技能精简

**AGENTS.md**：删除「分支名不含斜杠」约束（本机环境特有，不应进全局文件）；「版本控制」段保留 reflog 恢复顺序与 pack-refs 两条通用实践。

**git-branch-diff-merge 技能**：339 → 235 行重写。修掉两个**实测确认**的硬缺陷：

- `git diff --diff3` 在本机 git 2.55.0 直接报错（exit 129，unknown option）→ 改为普通 `git diff <BASE> <branch>`。
- `BASE=$(git merge-base ...)` + 后续用 `$BASE` 是错的：**shell 变量不跨工具调用存活**（已实测：一次调用 export 后下一次读为空），会让命令静默退化成「工作区 vs 单分支」——结果错但不报错 → 改为「抄下哈希，后续命令用字面量替换」。
- 另修：`git branch -b`（不存在该开关）→ `git branch -c/-C/-d/-D/-m/-M`；注释示例 `//` → 按目标语言注释符。
- 新增「停止条件」「失败处理」两段（原技能缺失）。
- 合并重复表述：核心目标 / 红线 / 注意事项 / 禁止动作原本把同一批规则各说一遍。

**agents 审计（第三轮已全部修复）**：

- `reviewer.md` 门禁状态判定表有空洞：P1 CONFIRMED 无对应状态；tester 产出的 `PASSED_WITH_WARNINGS` 不是该表任何一行的输入。且门禁判定在 `AGENTS.md` / `tester.md` / `reviewer.md` 三处各写一份（违反单一维护源）。

## 第三轮：按行业最佳实践修复 agents 审计发现

**门禁状态模型单源化（核心）**：原设计有三处问题——判定规则在 `AGENTS.md` / `tester.md` / `reviewer.md` 各写一份；reviewer 的表试图算全局 `GATE_STATUS`（越权，它只该判自己那一半）；且该表**接不住** P1 CONFIRMED 与 tester 产出的 `PASSED_WITH_WARNINGS` 输入。

改法：`AGENTS.md`「门禁状态定义」成为唯一维护源，定义四个取值与全序合并规则；tester / reviewer 各自只判自己那一半（`PASSED` / `PASSED_WITH_WARNINGS` / `FAILED`），只引用不重复。合并取「更严格者」是对全序集取 max，**组合空洞从结构上不再可能**。

- 新增 `PENDING` 状态：任一半为「待测试」/「待审查」即 `PENDING`（门禁未完成，不得提交）——原设计在这一格上无定义。
- reviewer 的判定表改为穷尽三行：有 P0 CONFIRMED → FAILED；无 P0 CONFIRMED 但有 P0 PLAUSIBLE / P1 CONFIRMED / P1 PLAUSIBLE → PASSED_WITH_WARNINGS；仅 P2/P3 或无问题 → PASSED。
- `coder.md` 门禁表补 `PENDING` 行，并把「用户已明确下令提交」设为前置条件（原文「PASSED → 正常提交」与 AGENTS.md 全局禁令冲突）。
- `coder.md` 删除死链 `algorithmic-art`；15 个被引用技能全部核验存在。
- 5 个 agent 的「Skills 维护源」说明统一为逐字相同的一行（md5 已比对一致），指向 `AI_READ_FIRST.md`。
- 额外发现并修复：`reviewer.md` 说「报告不存在 → 创建新报告」但完整模板只在 `tester.md`，补上文件头要素。
