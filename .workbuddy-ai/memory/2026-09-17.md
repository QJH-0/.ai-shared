# 2026-09-17 — .ai-shared 治理规则加固

## 本次改动（唯一维护源 `C:\Users\20448\.ai-shared\`）

### 1. AGENTS.md

- **「安全与版本控制底线 → 版本控制」新增切分支三道闸**（源自 2026-09-17 本机 `git checkout` 物理删除已跟踪文件的事故）：
  ① 切前 `git status --porcelain -uall` 必须为空；
  ② 未提交改动先提交到当前分支，或 `git stash push -u -m "<说明>"` —— **`-u` 不可省**，`git stash` 默认不含未跟踪文件，而新建文件正是最容易无声丢失的一类；
  ③ 切后校验 `git status` 无成片 ` D`，抽查关键目录已跟踪文件仍在磁盘上。
  附禁止项（带改动直接切、`-f`/`--discard-changes`、`reset --hard`、`clean -fd`、把 stash 栈当分支备份）与止损（`git checkout HEAD -- <path>`；严禁 reset/clean/re-clone）。
- **「多 Agent 协作」新增「委派边界（唯一维护源）」小节**：
  - 派发层级只有两层：用户 / analyst 是编排方；coder / reviewer / tester / researcher 默认不得再派发。
  - 唯一例外：只读检索（子代理不得写文件；写入报告或门禁的关键项须本人复核原始证据；涉执行/验证/结论判定即失效）。
  - 门禁与验证结论不可委派；派发简报四要素（objective / output format / tools & sources / boundaries）；成本边界（多代理 ≈ 15× token）；并行边界（所有权不重叠才可并行，不得同时派发多个实现型子代理）。
- 「全局禁止项」原门禁委派条目改为指针，避免同一规则两处定义。

## 调研依据（行业最佳实践）

- **Anthropic《How we built our multi-agent research system》**：多代理系统 token 消耗约为普通对话的 **15 倍**；委派必须给 objective / output format / tools & sources / task boundaries 四要素，否则子代理会重复劳动或留空档；明确「大多数编码任务真正可并行的子任务比研究少，LLM 尚不擅长实时协调委派」。
- **Claude Code subagent 官方文档**：嵌套委派默认最多 3 层（`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` 可调），在深度限制处会**扣留 `Agent` 工具**；官方建议对「应保持只读的审查者」直接从 `tools` 移除 `Agent`。
- **`superpowers:subagent-driven-development`**：worker 永不派发子代理；实测中每个 worker 自派的审查者都是重复席位。
- **`git switch` 官方手册**：「不要求索引与工作区干净，但若会导致本地修改丢失则中止」，除非显式 `--discard-changes` 或 `--merge`。
