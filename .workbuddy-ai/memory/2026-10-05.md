## 修复：MCP 同步改为双向 + 清掉 context7 残留

### 关键约束：不能靠内容特征区分自管段

Codex 自管的 `[mcp_servers.node_repl]` 同样带 `startup_timeout_sec = 120`，
与脚本渲染的块**无法靠内容区分**——按「带 120 就是脚本写的」这种启发式会误删它。
所以必须有**显式名单**。

### 方案

新增 `.ai-shared/.mcp-synced.json` 记录脚本写过的 server 名（**需入库**）。
每次同步：`stale = 名单 − 源里的键`，stale 从派生端删除；删完把名单更新为源里的键。
Codex 侧删除同时覆盖子段（`[mcp_servers.<n>.env]`）。

### 踩坑：往返测试抓到空行丢失

首版删除逻辑顺手把「段前空行」也吃掉，导致「插入 → 删除」不能逐字节回到原状
（断言 `removed == orig` 失败）。修法：**段前空行保留作分隔，只吃段后的空行**。
没有这个往返断言，这种不对称会一直潜伏到某次 diff 才暴露。
